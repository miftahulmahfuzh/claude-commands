# P2-CL-A019 — remove the phantom `spawn --isolate` from `/analyze-orchestrator`

**Card**: [miftahulmahfuzh/claude-commands#7](https://github.com/miftahulmahfuzh/claude-commands/issues/7)
**Round**: P2-CL-A019 round 1 — 2026-10-27
**Branch**: `task/7-swarm-py-spawn-has-no-isolate-but`

## The defect

`commands/analyze-orchestrator.md` Step 4 instructs the coordinator to spawn phase sessions with
`swarm.py spawn --isolate` in three places. `swarm.py` defines no such argument, so argparse
hard-errors and the wave never spawns. Because the failure is at coordinator level, iron rule 4's
arithmetic makes it a whole-set stall rather than a one-phase one — and it lands precisely on the
ISOLATE remedy, i.e. exactly when two concurrent phases write one file, the case the write-set
gate exists to catch.

Step 3b (`:291`) already carries a correction note added by the `swarm-write-set-gate` plan set.
That note is the workaround; this card is the fix.

## Evidence gathered before deciding

- `grep -c isolate skills/swarm/swarm.py` → `0`. Installed copy agrees — not deploy drift.
- `spawn`'s argparse (`skills/swarm/swarm.py:2113-2124`) defines exactly
  `--slug --phase --prefix --prompt --cwd --permission-mode --model --force --no-trust --dry-run`.
- **The card's one "Unverified" item is now verified.** `git log --oneline --all -S'isolate' --
  skills/swarm/swarm.py` returns **nothing**, while the control `-S'--no-trust'` on the same path
  returns two commits. The flag was never implemented and later removed — it was only ever
  written into the docs.
- `cmd_spawn` (`swarm.py:852`) resolves `cwd = args.cwd or real_path(ledger.get("worktree")) or
  repo`. So the shared-worktree default is "no `--cwd`", not "no `--isolate`", and `--cwd` is
  already a complete isolation mechanism.

## Approaches considered

### A — Implement `--isolate` in `swarm.py spawn` (rejected)

Cut the worktree from the integration branch, provision it, pass `--cwd` internally.

Lost on three counts, each from the repo rather than from taste:

1. **`swarm.py` does not know the integration branch.** The ledger records the *set's* worktree,
   not the per-wave integration branch that Step 4c moves. `--isolate` would therefore need
   `--from <branch>` handed to it — which is `git worktree add` with extra indirection, not less.
2. **It would create a second provenance for provisioning knowledge.** The per-repo ladder (own
   virtualenv, **hardlinked** not symlinked `node_modules`, runner path pinning) already lives in
   `agents/integrator.md` step 4, keyed on `.workflows/swarm.json` `suite.setup`. Duplicating it
   into `swarm.py` is the two-provenances problem CLAUDE.md names as the repo's central
   invariant, in a new place.
3. **Unverifiable here.** This repo has no CI; a new spawn path that cuts real worktrees and
   opens real tmux windows cannot be proven by the offline `selftest` suite that is the whole
   gate. A behaviour change to the helper that drives unattended overnight runs, landed without
   a test that exercises it, is a worse trade than the prose fix.

### B — Fix the three doc sites, delete the flag from the vocabulary (chosen)

Rewrite Step 4's three `--isolate` sites to the `git worktree add` + `spawn --cwd` form that
Step 3b already specifies and that the `swarm-write-set-gate` set actually used for its own
wave 1. Correct immediately, strictly smaller, and makes the document self-consistent instead of
carrying a correction note that contradicts its own Step 4.

### C — Add `--isolate` as a deprecated no-op alias (rejected outright)

Would stop the argparse error while silently delivering no isolation — a green spawn with
concurrent phases sharing a tree is strictly worse than the hard error, which at least fails
loudly.

## Ambiguity call (narrowest reading)

The card offers A and B and explicitly declines to decide. The narrowest reading that fully
satisfies the words on the card is *"a coordinator that follows Step 4 literally must not
hard-error"* — satisfied entirely by B. A would additionally change `swarm.py`'s behaviour, which
the card describes as the better end state **only** "if per-phase isolation is meant to be
routine" — a premise nothing in the repo establishes. Recorded on the card; if routine per-phase
isolation is wanted, that is a new card for `swarm.py`, not this one.

## The edits

All in `commands/analyze-orchestrator.md`.

1. **Step 4 site A** (the Isolation paragraph, `:439-440`) — replace "`spawn --isolate`
   provisions it" with the two-command form in a bash block, and say plainly that the
   provisioning below is the coordinator's to do, pointing at `agents/integrator.md` step 4 and
   `.workflows/swarm.json` `suite.setup` as where that knowledge lives.
2. **Step 4 site B** (`:457-458`) — "still what `spawn` does without `--isolate`" →
   without `--cwd`, naming the ledger fallback, which is what `swarm.py:852` actually does.
3. **Step 4 site C** (`:586`) — "only with `--isolate`" → only where each phase ran in its own
   worktree.
4. **Step 3b note** (`:291-297`) — keep the verified fact that the flag does not exist (cheap
   insurance against reintroduction) and the working form; drop the now-false cross-reference
   claiming Step 4 names `--isolate` at `:237`, `:255`, `:383`.

**Not touched:** `SWARM_WRITE_SET_GATE_PLAN.md`, `.workflows/orchestration/swarm-write-set-gate/`,
`.workflows/plan/swarm-write-set-gate/`, `.workflows/plan/P1-CL-A023.md`, `.workflows/todos.md`
history entries. Those are the landed record of a prior set; rewriting them would falsify
provenance, and `plan_graph.py`'s `isolate` verdict name is unrelated.
